# Map: Personal Podcast Tool

Tracker: local markdown. Tickets live in `wayfinder/tickets/`, research findings in `wayfinder/research/`.
Ticket files carry `status: open|closed`, `type`, `blocked-by`, `claimed-by`.

## Destination

A build-ready **spec** for the podcast tool: architecture, the skill's contract, the audio pipeline, hosting/delivery, and the episode format. Nothing left to decide before the follow-on skills (spec, tickets, implementation) take over. This map builds nothing.

## Notes

- Owner listens on iPhone and wants well-structured episodes, about 25 min by default, on **any general-interest topic**: sport, science, news, technology, finance, history and beyond. This is the tool's defining property, not a niche show (ticket 05, research/05 sections 12.1 and 13). Hard ideas are explained plainly enough for anyone.
- Owner summons a Claude skill with a topic. Claude researches and writes a finished, sourced bundle (script, metadata, sources). The tool is a pipeline from bundle to published audio.
- Constraints: as cheap as possible, no PC left running, not robotic, no App Store fee.
- Delivery direction (agreed): podcast RSS feed on GitHub Pages (public repo OK), subscribed in Apple Podcasts via "Follow a Show by URL", offline downloads handled by the app.
- Audio direction (agreed in principle): open-source neural TTS run in GitHub Actions, no paid API, engine kept swappable. Quality is unproven, see TTS research ticket.
- Use terms from `GLOSSARY.md`.
- **Human feel (owner, 2026-10-29):** everything (content, audio, interface, and the build itself down to code) must feel human, real and very engaging, with no AI slop. Researched in ticket 18, whose checklist every later ticket applies.
- **Leniency rule (owner, 2026-10-29):** numeric limits anywhere in the spec are soft targets with about ±25% leniency, unless they protect accuracy, honesty or the TTS engine. Ask the owner before introducing any strict limit.

## Decisions so far

- [Episode length evidence](tickets/01-episode-length-evidence.md): no direct audio evidence on length, so tunable; the segment arithmetic is superseded by ticket 05, so length and segment count follow the topic (research/05 12.3); recall prompts redesigned as retrieval (research/01).
- [Host format and engagement](tickets/02-host-format-and-engagement.md): single host, written conversationally with the listener's questions simulated in one voice; two-host benefit is fragile and unproven for audio; 13 style rules in the research file.
- [RSS, GitHub Pages and Apple Podcasts](tickets/04-rss-github-pages-apple-podcasts.md): public obscure feed followed by URL; mono AAC/MP3 ~10-15 MB per episode; Pages 1 GB cap means ~70-100 episodes; range requests work, iOS offline needs a real-device check; 11 constraints in the research file.
- [Open-source TTS on GitHub Actions](tickets/03-open-source-tts-on-github-actions.md): Kokoro-82M (kokoro-onnx, int8, CPU) on free Actions runners, ~10-25 min render per episode; chunked, silence-based pacing; Piper rejected on sound quality; Polly later dropped by ticket 09.
- [Research and accuracy standard](tickets/06-research-and-accuracy-standard.md): source ladder, 3-5 sources with every claim traceable, evidence strength voiced, never refuses or stops on risky topics (cautious framing plus show-notes flag), cheap claim-check against a claim ledger, owner gives only a topic with at most one short drill-down round if it is too broad (amended by 05: one confirm reply that also carries any drill-down; news rules and per-field source profiles added; review recommendations 1-5 signed off: read depth per ledger line, spoken numbers from full text or a stating abstract, load-bearing numbers re-checked, retraction check, n and population, `consensus` marker).
- [Episode template and style guide](tickets/05-episode-template-and-style-guide.md): any-topic, domain-neutral template with 15 starter source profiles. Quick 8-15 / Standard 15-28 (typ. ~25) / Deep 28-35 min, no minimum and no padding; split above ~35 min into standalone subtopic Parts. The skill proposes length and outline, and the owner confirms in one reply. Plain language first (explain then name, analogy for every hard concept). Retrieval by opening question and re-ask per segment. Soft ±25% limits, with only accuracy and TTS rules firm (research/05 sections 12-13; evidence for retrieval in research/17).
- [Skill runtime and summon surface](tickets/13-skill-runtime-and-summon-surface.md): Claude Code cloud session started from the Claude iPhone app's Code tab; Skill committed in the repo; push through the Claude GitHub App proxy (no token); environment needs Full network access; fallback is the Claude Code GitHub Action driven from issues; optional iOS Shortcut fires a scheduled task's API trigger as the summon button; no money beyond the plan; Shortcut accepted as optional; plan usage measured in a pilot on the first real Episode (see research/13).
- [Audio storage and retention](tickets/08-audio-storage-and-retention.md): audio never in git; one GitHub Release per episode is the permanent archive; deploy copies a window (~600 MB soft, ~900 MB firm site ceiling) into Pages, which serves the feed enclosures; leaving episodes drop from the feed, or repoint to Release URLs if the Apple test passes; archive page plus `pinned.txt` restore; 64 kbps mono AAC; titles `Episode N: Title`, Parts `4a/4b`, no `itunes:episode`; Bundles kept in git, no WAV masters.

- [Voice audition](tickets/09-voice-audition.md): main voice Kokoro `bm_george` (`bm_lewis` backup), plus Pocket TTS `charles`, `stuart_bell` and `alba` for some topics; Claude proposes the voice in the confirm step; both engines in the Pipeline; no Polly; longer chunks (up to ~300 characters) with drawn gaps and speed jitter, never fixed gaps; pace stays ~165 wpm and the owner fine-tunes speed in Apple Podcasts (0.1× steps on iOS 26); the owner wants a non-monotone delivery, now ticket 19.
- [Expressive delivery](tickets/19-expressive-delivery.md): keep bm_george with ticket 09 pacing; the owner judged the baseline more human than a prosody graft, reworded text, Chatterbox and Pocket at higher temperature; no engine change, no cloning, no split renders; measured pitch spread doesn't predict what sounds human; wording devices stay light-touch (research/19).
- [Human feel and AI de-slop](tickets/18-human-feel-and-ai-deslop.md): named tells per layer (content, audio, interface, build) with fixes; the main fix is a sourced surprise, a concrete case and a committed view in each segment, plus a versioned phrase list; softenings for research/05 devices that produce slop; kokoro-onnx gives per-chunk speed and phoneme input, with no SSML or timing output; soft pause defaults with jitter, breaths off pending an A/B test in 09; cheap three-point lint; firm rules F1-F9 signed off, and only the F9 core ten phrases block on style; softenings applied in research/05 12.11; humour zero to two light moments; breaths off in v1.
- [Agent learnings repository](tickets/10-agent-learnings-repository.md): Learnings are lessons (a mistake or difficulty plus what to do instead), never topic facts, from any stage the skill runs; a smooth run writes nothing; `learnings/INDEX.md`, `general.md` and one file per field holding its source profile; ~3-5k tokens read per run (soft); auto-written in the Bundle commit with a "Learned this run" block; the skill may only tighten profile safety triggers (firm); new profiles start as drafts with the strictest neighbour's triggers; outlets named only for observed errors; self-correcting with `seen` counts; owner-sourced lessons are protected.
- [Bundle contract and pipeline architecture](tickets/07-bundle-contract-and-pipeline-architecture.md): Bundle is a folder (`script.md`, `meta.yaml`, `show_notes.md`, `ledger.md`, `lint_report.yaml`) with the research/05 markup unchanged; the session pushes a `claude/` branch that auto-merges only for `bundles/`, `learnings/`, `pinned.txt`; the Pipeline numbers episodes at publish into `episodes.yaml`; auto-merge, publish-episode and deploy-site chain by dispatch; one engine installed per voice; long chunks with Pipeline-owned drawn gaps; failures open an issue, success is silent; Python `pipeline` package with one shared lint; repo `podcast` laid out to the Matt Pocock conventions (GitHub Issues tracker, `docs/agents/`, deep-module entry points).
- [Show identity and feed metadata](tickets/12-show-identity-and-feed-metadata.md): *Plainly Put*, author is the show name, no owner email; `en-GB`, Education, not explicit, episodic, no seasons; the channel description states once that Claude writes and a synthetic voice reads; typographic code-drawn cover (ink blue, cream serif, owner approves the PNG); no sting, music or show line in v1; host unnamed; one-line CC BY voice credits in show notes; light `suits:` hints with `bm_george` default; Q&A episodes `Episode 7q` (then `7r`...), `4q` for split topics, `episodeType` `bonus`; `itunes:block` and `podcast:block`, `robots.txt` disallow, `noindex` archive page, public repo history accepted.
- [Q&A episodes](tickets/11-qa-episode-skill.md): a Q&A mode of the same Skill, in the same Feed (`Episode 7q`, `bonus`); the owner names a published parent by number or title words plus several questions; for depth, not corrections (errors still said plainly); unlinked questions recommended as normal Episodes; one segment per question, answer first after a short reminder of the parent, ~4-8 min per question (soft); parent ledger cited by reference plus 2+ new sources per question (soft); parent's voice; new `config/listener_profile.md` logs what the owner asks for and proposes default changes for owner OK.
- [Feedback loop and published corrections](tickets/16-feedback-and-corrections.md): feedback mode of the same Skill, free text read back in one line; routed to Listener profile (widened to all taste), Learnings, lexicon, `suits:` or phrase list; instructions apply at once, reactions proposed after ~3; Skill asks only after a change; errors found by owner, Q&As and an overlap check; Harmful/Material get a same-guid `-v2` re-render with minimal edit and dated show-notes line (Harmful also a spoken line), owner confirms; Minor gets a notes line; no correction episodes; `revision` bump auto-dispatches the re-render; whole Episode family fixed at once; downloaded copies stay stale, so re-download.
- [Pronunciation lexicon and text normalisation](tickets/14-pronunciation-and-text-normalisation.md): spoken form plus a firm lint (digits, symbols, abbreviations, fillers, unverified capitals) fixes numbers, units, times and money in all five voices; `config/lexicon.yaml` holds a `verified:` capitals list and `{term, kokoro, pocket, by, note}` entries, one field per engine because respellings that help Kokoro garble Pocket; Kokoro gets espeak phonemes spliced in with a stand-in word and `is_phonemes=True`; the Bundle's `pronunciations` uses the same shape; acronyms in plain capitals, not hyphenated; Skill and owner feedback add entries; names still need the owner's listen (research/14).
- [Pipeline testing and audio quality gates](tickets/15-pipeline-testing-and-quality-gates.md): ASR round trip (`base.en`) on the encoded file gates on the longest run of missing Script words, not WER (1-3 clean, 8-24 broken); separate silence check; two-pass loudnorm to -16 LUFS with a limiter, 24 to 44.1 kHz; Python feed checks before deploy and a HEAD/range smoke check after; pytest, smoke Bundle, `dry_run` and a test feed for testing without publishing; one real-device checklist; the six audio and format fails are firm, and an ASR fail re-renders the named chunk once before an issue opens (research/15).

- Topic backlog (owner, 2026-10-29): `config/backlog.md`, a plain list only the owner adds to, by hand or through the Skill ("add to backlog: X"). Summoning with "next" takes the top line, which still goes through the confirm step. The Skill offers unlinked Q&A questions (ticket 11) for the backlog and adds them only on a yes. It never suggests topics itself.
